Technical foundations for GEO

When search engines can reliably retrieve a page and read its content (including structured titles, author, dates, links, and canonical URLs), retrieval‑based AI models (e.g., OpenAI's ChatGPT, Anthropic's Claude, home‑grown models like Apertus) can surface that work more often, reducing the risk that pages appear only in training datasets without any real‑time visibility. Provider‑specific controls (e.g., block‑level robots.txt or privacy‑controlled PDFs) are preserved and documented so that institutional policy never becomes an obstacle; meanwhile, optional AI‑friendly files (llms.txt) give a lightweight way for researchers to invite AI services to look for evidence while keeping core compliance unchanged.

Distribution and measurement for AI visibility

Existing researcher posts, partner‑site announcements, press releases, conference abstracts, and independent coverage already feed robust discovery streams. The simplest lift comes from linking directly back to the maintained evidence page (e.g., the canonical model card, the final paper PDF, or the evaluation code repository) whenever a new overview appears. No new social‑media cadence, no new brand‑positioning push, and no external marketing budget is required—just a habit of inserting a one‑sentence annotation: “Full details → https://…”.

  1. Core prompts (6‑10 items) – Open‑source foundation models, trusted reasoning services, peer‑reviewed alpine research on AI for science, CSCS infrastructure documentation, joint‑initiative news, and queries framed both branded and unbranded.

  2. Execution estimate – 5‑minute copy‑paste effort per prompt run; totals ~20‑40 minutes monthly. Run these prompts in a notepad; record the exact interface (Web UI vs GPT‑API, language setting).

  3. Observation data – Date, product name, model (if displayed), interface type, language, verbatim prompt, response excerpt (or plain text version of model reply), and citation URL (or “not‑found”).

  4. Assessment flags – Cited via institution‑owned source, mentioned without citation, omitted, or not assessed. A “not‑reviewed accuracy” wording is attached. Calculate citation rate = cited assessments ÷ assessed pairs; representation = cited + mentioned assessments ÷ all assessed pairs; issue rate = inaccurate‑/misattribution assessments ÷ accuracy‑reviewed assessments.

  5. Caveats – Citation/mention percentages are a snapshot only; they are not “share‑of‑voice,” cut‑off calls, or industry benchmarks. Android app referrers, API‑usage, and model‑card views give complementary but incomplete signals.

Monthly checklist

  • Re‑run prompts from month‑ago list.
  • Flag any page newly blocked or redirected.
  • Correct canonical links that diverged.

What triggers action

  • Repeated omission on genuinely relevant queries.
  • Persistent misattribution of work to another team/institution.
  • Outdated date in citation URLs that no longer matches the current paper version.
  • Confirmed access failure (status 403/404) blocking a potentially valuable source.
  • AI product behavior change that appears unrelated to content update and yet alters the answer set.

Editorial Guidelines

Concise, scannable answers sit near the top of every relevant page; headings and bullet lists appear where they clarify data or workflows; quantitative statements give date, context, and source; expert quotations are invoked only when they add interpretive value; every primary artifact (paper, model card, code, evaluation suite) is linked directly from the page with a one‑line caption that matches that evidence. Scientific nuance is preserved; no extra length, mandated FAQs, or statistical guarantees are prescribed.

Pages plainly state the responsible institution and the actual authors/contributors; joint‑project roles are listed once and consistently; duplicate initiative pages are left separate unless the institutions jointly agree on consolidation; structured‑data tags are added only when they map directly to visible content; no blanket “FAQPage” markup is imposed; the “llms.txt” or similar AI‑specific files are optional experiments, not prerequisites; policy decisions about additional services are logged against existing workflow ownership.

Five immediate actions

  1. Update robots.txt & status – Web Team to audit current robots.txt for blocking search engines; revise any blocking rules; note every change with comment “AI discoverability review 2024‑06”.
    Definition of done: A consolidated note file created; any blocked URLs changed to ‘Allow’ or explicitly documented as blocking with rationale.

  2. Add missing structured data on model‑card pages – Editor to tag Organisation, Person, ScholarlyArticle schema on EPFL, ETH, CSCS, and SNAI model‑card URLs; ensure each Person.url points to the author page.
    Definition of done: Each model‑card page passes the Google Structured Data Test without new errors; reference to the updated schema version stored in doc/model‑schema.json.

  3. Publish a canonicalisation note – Editor to post a short notice on each partner site that lists the single canonical URL for the initiative they represent (e.g., https://scien.su/initiative in the Alps/CSCS context).
    Definition of done: Notice added to footer of all relevant pages with link to canonical; no further consolidation required.

  4. Create a monthly dataset record – Web Team to build a markdown snapshot (AI_discovery_monthly.md) from the routine described in focus area 7; include prompts, dates, citation indicators, AI product names and language, and timestamp of last content update.
    Definition of done: One CSV or markdown row per measurement instance placed in the shared repo; row added within 24 hours after measurement.

  5. Add a note to the “llms.txt” optional file – Web Team to add a one‑line entry (e.g., SwissAIInitiative: https://scien.su/docs) to the optional public file at https://example.com/.llms.txt (or partner‑specific equivalent); label it “experiment: optional discovery invite”.
    Definition of done: One line placed and versioned; no changes to existing robots.txt required.
