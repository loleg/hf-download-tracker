Synthesis

Conclusion & priorities for the rebuild

Written independently on the same day, the three reports converge on one diagnosis and split usefully by altitude: the content is strong; the navigation routes by artifact instead of intent — so people cannot reach the docs, the showcase, or a way to contribute without reverse-engineering the site.

Where all three agree

  • Navigation is organized around the site’s own artifacts, not visitor intent.
  • The documentation — the site’s best asset — is mislabeled (“Documentation” leads to downloads) and buried (breadcrumbs off, five-level sidebar).
  • The community showcase is missing from the main nav, and its page title is literally wrong.
  • There is no contribution route in the primary IA — the largest gap against the stated goals.
  • Fix the information architecture before commissioning any visual redesign.

Recommended priorities

  1. P0 — this week: verified one-line repairs. Showcase title in get-showcase.md, the /docs/FAQ 404 in contact.md, a skip link in baseof.html, breadcrumbs = true, replace the theme placeholder description, make the SGLang example version-consistent, label the newsletter email field. Zero-risk fixes that currently erode trust.
  2. P1 — next 2–4 weeks: the intent-based navigation decision. Adopt one merged structure — Try Apertus (prominent) · Docs · Models · Research · Showcase · Contribute · About — with Contact in the footer and search surfaced in the header. “Get Started” becomes a decision page routing to use via provider / run locally / build an app. GLM’s minimal set and ChatGPT’s Models/Build/Docs discipline are compatible; pick one and keep labels canonical.
  3. P2 — next 1–2 months: content systems. Standardized app and provider listings (operator, requirements, version, privacy/source, last-checked), a Contribute landing page with a staffed receiving route, research regrouped by topic with artifacts (paper, code, data, citation), unify /pages and /docs, flatten the sidebar, homepage copy rewrite, and a maintainable localization assessment.

Guardrails

  • Preserve deep links with redirects; publish the migration map before moving anything.
  • Do not promote a contribution invitation before the receiving process exists and someone owns review.
  • Assign a content owner per section — a better menu exposes more content and raises the maintenance bar.
  • Validate with task-based tests (find an app, an endpoint, a model, an artifact, a contribution task) after P1, before expanding scope.

Apertus: Final Verdict

    Navigation Fix Should Come First: Do not trigger a visual redesign or a color-scale pivot until the information architecture clearly serves Try vs Build vs Contribute personas.
  • Immediate (This Week): Rename or rearrange primary CTA buttons, fix the mixed-model documentation line, and add explicit language-disclosure on external providers.
  • Next Sprint: Build “Try Apertus” and “Contribute” pages that are discoverable in the main nav, keeping existing deeper docs as auxiliary links. This is the primary bottleneck users cite.
  • Longer Term: Once the pathways are obvious and accessible, layer improved styling and persona-specific messaging rather than guessing where users go today.

    • All three reports agree: open methodology does not equal open pathfinding. Use the existing palette (#7BBBD5, #FF0000, #2E2F31) but shape journeys around user goals.
