# Apertus Website — Navigation & IA Review

**Date:** 6 November 2026
**Scope:** apertus-ai.org (live site + `www-apertus` Hugo repository)
**Reviewer:** Automated audit against stated goals: *inclusive, accessible presentation that drives exploration of models/research, community apps, inference endpoints, and open-source contribution.*

---

## 1. Executive Summary

The site's visual design and content depth are genuinely strong — the hero is clean, the docs are substantial, and the writing is good. The navigation, however, does not serve that content. The single biggest problem: **the top-nav item "Documentation" does not go to the documentation.** It goes to a model-downloads page (`/pages/documentation/`), while the real documentation lives at `/docs/` and is reachable only via in-text links. Compounding this, the "Get Started" CTA sends developers to a hosting-provider directory instead of a technical quickstart, the community showcase is not in the nav at all, there is no "News" item, and — most striking given your stated goals — **there is no navigation entry whatsoever for contributing to the open-source projects.** The result is a site where the best content is effectively hidden from the people it was written for. This is fixable with a modest restructure; the underlying content is already there.

---

## 2. What's Working

Before the critique, the strengths — because the restructure should build on them:

- **Clean, calm design system.** Pale sky-blue, generous spacing, restrained typography. It feels institutional and credible.
- **Substantial docs tree.** `/docs/` has real content: quickstart, user guides (Ollama, LM Studio, LlamaFile), inference guides (vLLM, SGLang, Transformers), deploy guides (Azure, Vertex, SageMaker, Exoscale), technical pages (fine-tuning, evaluation, safety), and an FAQ. This is the site's most valuable asset.
- **Honest, well-written copy.** The about page's roadmap and the research collection are serious and credible.
- **Working technical foundations.** Open Graph meta, Plausible analytics, SRI-hashed assets — the plumbing is in good shape.

---

## 3. Findings

### Critical — these mislead or block users

**C1. "Documentation" is a misnomer.**
The top nav's second item, "Documentation," links to `/pages/documentation/` — a page of Hugging Face download cards and GitHub repository links. The actual documentation is at `/docs/`, a completely separate section. A user who clicks "Documentation" and finds a download page has every right to feel cheated; the real docs are two clicks away, through links buried mid-page. This is the site's most consequential labeling failure.

**C2. "Get Started" goes to the wrong place.**
The hero's primary CTA — big, red, first — links to `/pages/get-started/`, which is a directory of inference providers (Swisscom, Infomaniak, Phoeniqs…). A developer clicking "Get Started" expects a quickstart; the actual quickstart is at `/docs/quickstart/`. The CTA currently serves partnership visibility rather than the user's task.

**C3. The community showcase has the wrong title.**
`content/pages/get-showcase.md` — the showcase gallery — has front matter `title: "Get Started"`, a copy-paste error. The live page's `<title>` and heading therefore say "Get Started" on the showcase page. Users and screen-reader users landing on the showcase get the wrong page identity.

**C4. News is invisible in the global navigation.**
The homepage is dominated by a news feed, yet the top nav has no News item. News is reachable only via the homepage's "More news posts" button and the footer. For a site that treats news as primary content, this is incoherent.

**C5. The Contact page links to a 404.**
`content/contact.md` links to the FAQ as `/docs/FAQ`. The real page is `/docs/faq/`. On the site's Apache server, `/docs/FAQ` returns a hard 404. The Contact page — a nav item — contains a dead link to one of the site's key resources.

**C6. No skip link, despite a fixed navbar.**
The navbar is `position-fixed` and `top-0` across the site, but there is no skip-to-content link anywhere — not in `head.html`, not in `baseof.html`. For keyboard and screen-reader users this is a WCAG 2.4.1 failure. On a site with this much content, it's also just poor ergonomics.

### Serious — these degrade the experience significantly

**S1. The footer is skeletal.**
One link ("Legal Notice") and a copyright line. No navigation mirror, no social or repository links, no sitemap. Users who reach the bottom of a long docs page have no way to get anywhere except scrolling back up. For a content site, the footer is free navigation real estate currently being wasted.

**S2. The search page is orphaned.**
`/search/` exists and works, but nothing links to it. I searched every content file and layout template; there is no reference. For a site with this many pages — docs, articles, research — surfacing search in the header is the single highest-leverage navigation improvement available.

**S3. Split-brain information architecture.**
The site has two parallel page systems: `/pages/*` (the marketing pages the top nav links to) and `/docs/*` (the real documentation, with its own sidebar). The two systems are not cross-linked in any systematic way. On top of this, the docs config sets `breadcrumbs = false`, so once a user is inside `/docs/`, they lose all orientation. There are effectively two sites stapled together, and the top nav only serves one of them.

**S4. The docs sidebar is over-nested.**
`layouts/partials/docs/sidebar.html` recursively nests five levels deep. Combined with disabled breadcrumbs, this makes the docs — the site's best content — the hardest section to navigate. The tree also mixes task-based groupings ("Deploy," "User Guides") with topic-based ones ("Tech") without a stated taxonomy.

**S5. Charter and Hackathons pages are orphaned.**
Both `/pages/charter/` and `/pages/hackathons/` are live, substantial pages linked only from in-text references. Neither is in the top nav.

**S6. Top-nav active states are hardcoded and miss the docs section.**
`navbar.html` sets the "active" class by exact string match (`eq $currentPage "/pages/documentation/"`). When a user is browsing any `/docs/...` page, no top-nav item highlights. The nav goes dark exactly when the user is deepest in the site's largest section.

### Minor — polish items

**M1. The research page is an unstructured wall.** Twenty-four-plus paper cards in a single flat grid, with no grouping by year, topic, or project. The eye has nowhere to start.

**M2. An orphaned draft with unvetted content.** `content/pages/quickstart.md` — an NGO-focused guide, not linked from the nav and not in the sitemap — sits in the repo with LLM-generated-looking content, invented statistics, and a mermaid flowchart. It's not live, but it's the kind of thing that leaks into production accidentally.

**M3. The docs section still has the theme's template description.** `content/docs/_index.md` carries `"Explore our guides and examples to deploy your Hugo site using the Lotus Docs theme"` — a placeholder string from the theme demo, live in the section's meta description.

**M4. Contact page email patterns.** The page uses `safety @ this domain` and `team @ this domain` constructions — a manually-obfuscated pattern that reads awkwardly and confuses copy-paste.

**M5. Mixed link syntax in about.md.** Markdown-style `[Documentation](/pages/documentation)` links sit alongside raw HTML anchors — a maintenance hazard.

## 5. Recommended Navigation Structure

**Proposed top nav (6 items + search):**

```
[APERTVS]   Get Started · Docs · Research · Showcase · News · About   [Search]
```

- **Get Started** → a proper decision page routing to: *use it via a provider* / *run it locally* / *build an app* (the current `/pages/get-started/` content becomes one branch of this)
- **Docs** → `/docs/` — reclaim the label for the real documentation
- **Research** → `/pages/research/`
- **Showcase** → `/pages/get-showcase/` — promoted from orphan; this is the community-apps goal
- **News** → `/news/`
- **About** → `/pages/about/`
- **Search** → `/search/` — surfaced in the header for the first time
- **Contact** → moves to the footer (it's a terminal page; it doesn't merit a nav slot)

**Hero CTAs:** keep the primary "Get Started" button but point it at the new decision page (or directly at `/docs/quickstart/`). The secondary "Showcase" button is already correctly aimed — keep it.

**Footer restructure:** mirror the six nav items, then add GitHub, Hugging Face, the newsletter, and Legal. One link today; it should carry the site's entire second-level navigation.

**Docs sidebar:** enable breadcrumbs (the config currently disables them), flatten the tree to at most three levels, and order it task-first: Quickstart → Use → Deploy → Develop → Reference → FAQ.
